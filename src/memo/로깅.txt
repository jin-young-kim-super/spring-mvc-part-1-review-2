Logback : 구현체
-> 스프링 부트는 Logback을 기본으로 사용


로거를 사용해야 하는 이유
1. 타임 스탬프, 쓰레드 명 등 여러 부가 정보를 제공 받는다.
2. 개발 서버/스테이징 서버/운영 서버 별로 보여주는 로그를 제어할 수가 있다.
3. System.out.print를 사용하면 모든 로그가 다 출력되기 때문에 성능/로그 가독성이 똥 된다.
4. 별도의 설정만을 통해서 콘솔뿐만 아니라 자동으로 로그 파일에 함께 저장하게 하거나, 로그를 네트워킹을 통해 다른 곳으로 보낼 수가 있다.
-> 어떤 구현체는 로그 파일의 용량 오버로 생기는 I/O 병목 현상을 해결하기 위하여, 일정 용량이 넘어 가면 새로운 파일로 로그를 자동 기록하는 기능들도 있다.

logging.level.hello.springmvcpart2=debug
1. log.trace("trace" + name);
2. log.trace("trace",name);
-> 실무에서는 절대로 + 연산을 하면 안된다.

log.trace("trace" + name)의 실행 흐름
1. name 치환 : log.trace("trace" + "kim")
2. 문자열 + [연산] : log.trace("trace kim")
3. 파라미터 전달
4. 어? trace이니깐 출력 안 해도 되구나
-> 출력도 안 하는데 연산이 일어난다.

log.trace("trace",name)의 실행 흐름
1. name 치환 : log.trace("trace" , "kim")
2. 파라미터 전달
3. 어? trace이니깐 출력 안 해도 되구나
-> 연산이 안 일어난다. 고로 실무에서는 절대 문자열 결합을 해서는 안 된다.
